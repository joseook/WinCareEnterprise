WinCare Enterprise

Diagnóstico e manutenção do Windows para técnicos. Versão 0.2.1. Open source (MIT).

Rápido: abra o PowerShell (como administrador, para aplicar otimizações) e cole 
irm https://wincare.joseok.cloud/run | iex

O script run é curto, legível e não executa nada além do install.ps1 desta versão, conferido pelo SHA-256 91A17278E24A87F74C1BD1AFF637615625C45F76BF8D69F4CEBBC4F6A59A1689.

Verificado: o hash fica do seu lado (auditoria, usuário sem privilégio) 
$f="$env:TEMP\wincare-install.ps1"; iwr https://wincare.joseok.cloud/install.ps1 -UseBasicParsing -OutFile $f; if ((Get-FileHash $f -Algorithm SHA256).Hash -eq '91A17278E24A87F74C1BD1AFF637615625C45F76BF8D69F4CEBBC4F6A59A1689') { powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File $f } else { Write-Error 'install.ps1 nao confere - nada foi executado' }
O que acontece
  1. O install.ps1 só roda se o SHA-256 bater. Ele baixa o pacote do GitHub Releases e confere a assinatura RSA do manifesto (chave fixada), o hash do zip e o de cada arquivo.
  2. Como administrador, a cópia verificada fica em Arquivos de Programas\WinCare (só administradores gravam); sem privilégio, em %LOCALAPPDATA%. Na interface, “Executar como administrador” reabre pelo mesmo caminho verificado.
  3. Abrir o WinCare não altera nada. Cada ação mostra a prévia e pede confirmação.

Usa -ExecutionPolicy RemoteSigned só no processo, sem Bypass: políticas de grupo, AppLocker e WDAC continuam valendo. Em máquinas corporativas com AllSigned ou AppLocker, veja o guia corporativo.
